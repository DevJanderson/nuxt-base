# Falhas conhecidas de CI — catálogo do projeto

Casos reais primeiro (com o commit da correção quando houver), classes conhecidas depois.
Ao resolver uma falha de ambiente nova, adicione a linha aqui **no mesmo commit**.

| Sintoma | Causa | Correção |
|---|---|---|
| `<binário>: not found` só no CI (`eslint: not found`) — **caso real, commit c898dd6** | Dependência implícita: peer auto-instalado pelo pnpm local, sem entrada própria no `package.json`; o CI não expõe o binário | Declarar o pacote explicitamente em `devDependencies` |
| `pnpm smoke` vermelho com `[request error] [fatal]` no log de produção a cada 404 — **caso real, commit 6286b20** | `createError({ fatal: true })` no catch-all `app/pages/[...slug].vue`: no SSR o `fatal` faz o Nitro tratar 404 como erro não tratado e logar stack trace (e o h3 ainda emite WARN em dev) | `fatal: import.meta.client` — o `fatal` só é necessário no client, para a navegação interna abrir a página de erro; `statusMessage` curto e ASCII (o h3 sanitiza texto longo), o pt-BR vai em `message` |
| `pnpm smoke` vermelho em `nuxt dev` com `Another Nuxt dev server is already running` | Lock do `nuxt dev` por diretório, disparado quando o dev está com o `pnpm dev` aberto | Já tratado: o script sobe o dev com `NUXT_IGNORE_LOCK=1` em porta sorteada. Se voltar, é sinal de que a variável se perdeu do `stepDev` |
| `pnpm smoke` vermelho no teto do `.output/server` | Dependência pesada nova no bundle do servidor (caso conhecido: `@nuxt/image` com sharp+ipx, 26 MB) | Conferir se a dependência precisa mesmo ir para o servidor; teto novo é decisão consciente — mudar `MAX_SERVER_MB` no topo do `scripts/smoke.mjs` com o porquê no commit |
| `pnpm smoke` verde local e no CI `timeout de 120s aguardando dev ficar pronto` — **caso real, commit e4dfb34** | No GitHub Actions o consola força cor ANSI e a linha `Local:` do `nuxt dev` vem com escapes entre `Local:` e `http`; a checagem de prontidão testava o buffer bruto | Filhos do smoke rodam com `NO_COLOR=1`/`FORCE_COLOR=0` e a prontidão casa no texto sem ANSI; reproduzir local com `FORCE_COLOR=1 pnpm smoke` |
| `pnpm smoke` vermelho em produção por `DeprecationWarning`/`ExperimentalWarning` do Node no stderr | Bump de Node (local e CI em versões diferentes): warning de processo sai em stderr, que em produção reprova casando ou não | Corrigir a causa (flag/API depreciada) ou, se for ruído do runtime sem ação nossa, entrada na `LOG_ALLOWLIST` do `scripts/smoke.mjs` com o porquê |
| `pnpm smoke` vermelho no derivado depois de adotar logger (pino + pino-pretty) | O logger imprime `WARN`/`ERROR` legítimos no stdout, e o regex `OFFENSIVE_LINE` os pega | Rodar o smoke com o logger em modo silencioso/JSON (variável de ambiente) ou allowlist específica para o prefixo do logger — nunca afrouxar o regex |
| `ERR_PNPM_OUTDATED_LOCKFILE` no install do CI | `pnpm-lock.yaml` fora de sincronia com o `package.json` (edição manual de deps sem rodar install) | `pnpm install` local e commitar o lockfile junto |
| `Ignored build scripts: <pacote>` e depois binário/hook faltando — **casos reais: esbuild, unrs-resolver, vue-demi, lefthook** | pnpm 11 bloqueia postinstall por padrão | Adicionar o pacote em `allowBuilds` no `pnpm-workspace.yaml` |
| `typecheck` falha no CI e não local (ou vice-versa) | Spec fora de `tests/nuxt/` (fora do include do tsconfig) ou `.nuxt/` desatualizado | Specs sempre em `tests/nuxt/`; rodar `pnpm exec nuxt prepare` |
| Teste com data/hora passa local e falha no CI | Fuso: o CI roda `TZ: UTC`; máquina local provavelmente UTC-3 | Reproduzir com `TZ=UTC pnpm test`; corrigir o teste/código (datas em ISO/UTC), não o fuso do CI |
| `knip` acusa dependência "não usada" que o app usa | Auto-descoberta do Nuxt (coleções `@iconify-json/*`, environments de teste, binários internos) — knip não vê import | `ignoreDependencies` no `knip.jsonc`, com comentário do porquê |
| Você leu "sucesso" mas o run falhou | `gh run watch \| tail` — o pipe substitui o exit code do gh pelo do tail — **caso real** | `gh run watch <id> --exit-status` sem pipe; confirmar com `gh run view` |
| Teste intermitente só no CI | Flakiness: rede real, timers reais, ordem de teste | `registerEndpoint` para HTTP (nunca rede real), fake timers, teste isolado |
| Dev server "validado" era outro processo | Porta 3000 ocupada por instância órfã; Nuxt sobe em outra porta — **caso real na sessão de bootstrap** | Conferir a porta no log do `pnpm dev`; matar pelo PID de quem escuta a porta (`ss -tlnpH`) |
| Config `vite.esbuild.*` sem efeito nenhum (nem erro) — **caso real: strip de console** | Vite 8/rolldown: transform e minify são do oxc; opções `esbuild` são silenciosamente ignoradas | Usar o equivalente rolldown/oxc ou `minify: 'terser'`; **sempre validar por inspeção do bundle** (marcador + grep no `.output/public/`), nunca só pela config aceita |
| Job `gitleaks` vermelho | Segredo (chave, token, senha) commitado — o scan cobre o histórico inteiro, não só o diff | Remover do código, **rotacionar a credencial** (já vazou no histórico) e, em repo público, reescrever o histórico; falso-positivo documentado entra em `.gitleaksignore` |
